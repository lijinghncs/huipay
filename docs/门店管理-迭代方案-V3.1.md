# 门店管理迭代方案（V3.1 - 独立表版）

> 版本：V3.1（在 V3 基础上改为独立表存储）
> 适用项目：汇聚付分账系统（huipay-monorepo）
> 适用范围：商户端门店管理 + 付款码/订单/分账关联

---

## 一、本次修订

### 变更点

门店数据从复用 `t_entity`（`entity_type='STORE'`）改为**新建独立表 `t_store`**。

### 修订理由

1. **领域边界更清晰**：门店是商户的子资源，与主体（商户/推广员/平台/ISV）的属性差异显著（门店有地址/经纬度/类型，主体关注 KYC/登录/钱包）
2. **避免主体表字段膨胀**：`t_entity` 已承载 KYC、登录、微信配置等"主体级"敏感字段，门店不应混入
3. **查询性能更优**：门店高频读写（列表/筛选/统计）走独立表，避免与商户数据相互干扰
4. **未来扩展灵活**：门店特有的属性（如营业时间、店长、设备列表等）无需挤进通用 JSON

### 兼容性说明

- `t_entity` 不再使用 `STORE` 类型（保留字段值兼容性，但不再写入新数据）
- 历史若有 STORE 类型数据保留不变（无历史数据，影响为零）
- 字段含义对比：

| 维度 | 原 V3（复用 t_entity） | V3.1（独立表） |
|------|------------------------|----------------|
| 主表 | `t_entity`（`entity_type='STORE'`） | `t_store`（新建） |
| 商户关联 | `parent_id` | `merchant_id`（直挂） |
| 门店号 | `entity_code` | `store_code` |
| 商户身份认证资料 | `kyc_data`（门店不需要） | 无 |
| 钱包 | 不开 | 不开 |
| 登录 | 不支持 | 不支持 |

## 二、迭代任务清单

### S1 后端：门店独立表与 CRUD

#### 1.1 新建迁移

```sql
-- 0017_create_t_store.up.sql
CREATE TABLE t_store (
  id              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  store_code      CHAR(32)        NOT NULL COMMENT '门店编码（系统生成，前缀 S）',
  merchant_id     BIGINT UNSIGNED NOT NULL COMMENT '所属商户主体 ID',
  name            VARCHAR(64)     NOT NULL COMMENT '门店名称',
  store_type      VARCHAR(16)     NULL     COMMENT '直营/加盟/合作',
  contact_phone   VARCHAR(32)     NULL     COMMENT '联系电话',
  region          VARCHAR(128)    NULL     COMMENT '所在地区（省/市/区）',
  address         VARCHAR(256)    NULL     COMMENT '详细地址',
  longitude       DECIMAL(10, 6)  NULL     COMMENT '经度（预留地图可视化）',
  latitude        DECIMAL(10, 6)  NULL     COMMENT '纬度（预留地图可视化）',
  status          TINYINT         NOT NULL DEFAULT 1 COMMENT '1=启用 0=停用',
  created_at      DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at      DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  deleted_at      DATETIME(3)     NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uk_store_code (store_code),
  KEY idx_merchant_status (merchant_id, status, deleted_at),
  KEY idx_name (merchant_id, name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='门店表';

CREATE TABLE t_store_audit_log (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  store_id      BIGINT UNSIGNED NOT NULL,
  merchant_id   BIGINT UNSIGNED NOT NULL,
  action        VARCHAR(32)     NOT NULL COMMENT 'CREATE/UPDATE/STATUS/DELETE/CODE_LINK',
  operator      VARCHAR(64)     NULL,
  detail        JSON            NULL,
  created_at    DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  KEY idx_store (store_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='门店审计日志';
```

#### 1.2 新增模块

- `internal/store/`（DDD 分层）
  - `repository/store_repo.go` — 数据访问
  - `service/service.go` — 业务编排
  - `handler/handler.go` — HTTP 接口
  - `domain/store.go` — 领域模型
- 接口（商户侧鉴权，读 `X-Merchant-Id`）：
  - `POST /v1/merchant/stores` — 创建门店
  - `GET /v1/merchant/stores` — 分页列表（名称/编码/状态筛选）
  - `GET /v1/merchant/stores/:id` — 门店详情
  - `PUT /v1/merchant/stores/:id` — 更新门店
  - `POST /v1/merchant/stores/:id/status` — 启停门店
  - `DELETE /v1/merchant/stores/:id` — 删除门店（**仅无关联码牌/订单**可删，软删除）
- **审计日志**：CREATE/UPDATE/STATUS/DELETE 写入 `t_store_audit_log`

在 `cmd/server/main.go` 注册 `/v1/merchant/stores/*` 路由

### S4 后端：分账引擎接入门店（修正语义）

- 分账执行器从订单读取 `store_id` 注入 `MatchContext`
- **关键修正（保留 V3）**：门店专属规则（`conditions.store_ids` 非空）必须**严格命中门店**才算 Match；通用规则（`store_ids` 为空）作为兜底
- 单元测试补充：
  - 门店A 命中门店A 专属规则（priority=10，store_ids=[A]）
  - 门店B 无专属规则时回退通用规则（priority=5）
- 分账执行记录透出 `store_id`，便于排查

## 四、关键业务规则

### 4.1 门店与码牌

- 码牌可属于或不绑定门店（**软约束**，兼容历史）
- 门店停用时弹窗确认码牌处置：
  - 选"否"：码牌**仍可收单**，订单仍带门店 ID
  - 选"是"：批量停用码牌（`status=0`）
- 门店重新启用：**不自动恢复**码牌
- 删除门店：**仅当无关联码牌与订单**可删（软删除）

### 4.2 分账匹配语义（保留 V3 修正）

```
门店订单到达分账引擎
  ↓
构造 MatchContext { MerchantID, StoreID, Channel, NowAt }
  ↓
遍历规则集合
  ├─ 规则 store_ids 非空：
  │   ├─ StoreID ∈ store_ids → 命中
  │   └─ StoreID ∉ store_ids → 不命中
  └─ 规则 store_ids 为空：
      └─ 视作"通用规则"，命中
  ↓
在命中集合中按 priority 倒序取首条
```

### 4.3 审计日志

`t_store_audit_log` 记录：
- 门店创建/更新/停用/删除
- 门店关联码牌变更

## 六、风险与应对

| 风险 | 应对 |
|------|------|
| 历史码牌未绑门店 | 后端允许 NULL，前端告警引导 |
| 分账规则无门店维度 | 修正匹配语义，避免通用规则"吃掉"门店订单 |
| 停用门店影响在途订单 | 订单状态不受门店状态影响 |
| 门店数量爆炸（>5000） | 分页 + 关键词搜索 + 按商户隔离 + KPI 缓存 |
| 删除门店数据孤儿 | 软删除 + 仅无关联数据可删 |
| 审计缺失 | 关键操作写入 `t_store_audit_log` |
| `t_entity` 历史 STORE 数据 | 无历史数据，无需迁移；字段保留兼容性 |
