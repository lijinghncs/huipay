# 门店管理迭代方案（V3 - 修正版）

> 版本：V3（评审后修正）
> 适用项目：汇聚付分账系统（huipay-monorepo）
> 适用范围：商户端门店管理 + 付款码/订单/分账关联

---

## 一、修订说明

V2 经专家评审后，针对 3 个 P1 问题做修正：

| 编号 | 原方案 | 修正点 |
|------|--------|--------|
| P1-1 | 创建码牌时强制选门店 | **软约束**：后端允许 `store_id` 为 NULL（兼容期），前端必填引导 + 历史数据告警条 |
| P1-2 | 停用门店时弹窗确认码牌处置 | **细化策略**：选"否"时码牌**仍可收单**；选"是"时批量停用；重新启用门店**不自动恢复**码牌 |
| P1-3 | 分账"无门店规则回退商户默认" | **修正语义**：门店专属规则（`store_ids` 非空）必须命中门店才算 Match，避免通用规则"吃掉"门店订单 |

补充 P2/P3 改进：详情页拆分、KPI 缓存、删除路径、审计日志。

## 二、迭代任务清单

### S1 后端：门店数据模型与 CRUD

- 新增 `internal/store` 模块（DDD 分层：repository / service / handler）
- 复用 `t_entity`（`entity_type='STORE'`，`parent_id=商户ID`），不开钱包
- 门店号生成规则：32 位唯一号，前缀 `S` 区别于商户 `M`
- 接口（商户侧鉴权，读 `X-Merchant-Id`）：
  - `POST /v1/merchant/stores` — 创建门店
  - `GET /v1/merchant/stores` — 分页列表（支持名称/编码/状态筛选）
  - `GET /v1/merchant/stores/:id` — 门店详情
  - `PUT /v1/merchant/stores/:id` — 更新门店
  - `POST /v1/merchant/stores/:id/status` — 启停门店
  - `DELETE /v1/merchant/stores/:id` — 删除门店（**仅无关联码牌/订单**可删，软删除）
- **审计日志**：新增/停用/删除 写入审计表（关键操作）

### S2 后端：付款码 ↔ 门店关联（软约束版）

- migration `0015`：`t_payment_code` 增加 `store_id BIGINT UNSIGNED NULL` + 索引
- `paymentcode` 服务 `CreateRequest` 增加 `StoreID`
- **后端**：允许 `store_id` 为 NULL（兼容历史数据）
- **前端**：创建弹窗默认必填，提示"绑定门店以启用按门店分账"
- **历史兼容**：列表对未绑门店的码牌显示**黄色告警条**
- 校验：门店归属当前商户；编辑时可切换门店
- 列表/详情返回门店名称

### S3 后端：订单记录门店

- migration `0016`：`t_order` 增加 `store_id BIGINT UNSIGNED NULL`
- `precreate-by-code` 下单时反查 code 的 `store_id` 写入订单
- 交易列表/详情透出门店
- 交易筛选器新增"门店"维度

### S4 后端：分账引擎接入门店（修正语义）

- 分账执行器从订单读取 `store_id` 注入 `MatchContext`
- **关键修正**：门店专属规则（`conditions.store_ids` 非空）必须命中 `MatchContext.StoreID` 才算 Match；通用规则（`conditions` 为空）作为兜底
- 单元测试补充：
  - 门店A 命中门店A 专属规则（priority=10，store_ids=[A]）
  - 门店B 无专属规则时回退通用规则（priority=5）
- 分账执行记录透出 `store_id`，便于排查

### S5 前端（merchant-portal）：门店管理页面

- `BasicLayout` 菜单 + `App` 路由新增 `/stores` 与 `/stores/:id`
- **列表页**：
  - 搜索 + 表格 + 启停 + 删除 + 分页
  - 头部 KPI：总门店数、启用中、本月新增（**独立 query + 60s 缓存**）
  - 状态 Tag：启用绿、停用灰
  - 表格斑马纹、空状态插图、移动端响应式
- **详情抽屉**（轻量）：基础信息 + 2-3 个 KPI（本月交易额、订单数、码牌数）
- **完整详情页** `/stores/:id`：
  - 基础信息
  - 统计概览
  - 关联码牌列表（可跳码牌详情）
  - 近期交易列表
- **新建/编辑弹窗**：表单校验（名称 2-40 字符、地址/电话可选）
- **停用门店交互**：
  - 弹窗列出受影响码牌清单
  - 选"否"：码牌仍可收单，门店状态停用
  - 选"是"：批量停用所有码牌
- **删除交互**：仅无关联数据时可删，否则按钮 disabled + hover 提示

### S6 前端：收款码关联门店 + 交易透出门店

- 收款码创建弹窗：门店下拉选择（**必填引导**）+ 搜索
- 收款码编辑：可切换门店
- 收款码列表：展示所属门店名（**点击跳门店详情**）+ 未绑门店**黄色告警条**
- 交易列表：展示门店名 + 筛选器增加"门店"维度
- 交易详情：展示门店信息

### S7 联调验证

- 后端 `go build` 编译 + 接口冒烟
- 前端 `pnpm build` 构建 + 浏览器逐页验证
- 跨场景串联：建门店 → 关联码牌 → 扫码下单 → 触发分账 → 验证分账规则命中

## 四、关键业务规则

### 4.1 门店与码牌

- 码牌可属于或不绑定门店（**软约束**，兼容历史）
- 门店停用时弹窗确认码牌处置：
  - 选"否"：码牌**仍可收单**，订单仍带门店 ID（用于后续分账匹配）
  - 选"是"：批量停用码牌（`status=0`）
- 门店重新启用：**不自动恢复**码牌
- 删除门店：**仅当无关联码牌与订单**可删（软删除）

### 4.2 分账匹配语义（修正版）

```
门店订单到达分账引擎
  ↓
构造 MatchContext { MerchantID, StoreID, Channel, NowAt }
  ↓
遍历规则集合
  ├─ 规则 store_ids 非空：
  │   ├─ StoreID ∈ store_ids → 命中
  │   └─ StoreID ∉ store_ids → 不命中
  └─ 规则 store_ids 为空：
      └─ 视作"通用规则"，命中
  ↓
在命中集合中按 priority 倒序取首条
```

**关键修正**：门店专属规则必须严格命中门店，避免通用规则"吃掉"门店订单。

### 4.3 审计日志

关键操作需记录：
- 门店创建/更新/停用/删除
- 门店关联码牌变更

## 六、风险与应对

| 风险 | 应对 |
|------|------|
| 历史码牌未绑门店 | 后端允许 NULL，前端告警引导，过渡期后再考虑强校验 |
| 分账规则无门店维度导致历史订单错配 | 仅新订单生效，旧订单按原规则 |
| 停用门店影响在途订单 | 订单状态不受门店状态影响 |
| 门店数量爆炸（>5000）影响列表性能 | 分页 + 关键词搜索 + 按商户隔离天然分片 + KPI 缓存 |
| 删除门店数据孤儿 | 软删除 + 仅无关联数据可删 |
| 审计缺失 | 关键操作写入审计表 |
