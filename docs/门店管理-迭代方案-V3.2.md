CREATE TABLE t_store_audit_log (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  store_id      BIGINT UNSIGNED NOT NULL,

#### 1.2 store_code 生成算法

- 格式：`S` + 14 位时间戳（`YYYYMMDDHHMMSS`）+ 8 位随机数字 = 23 位，补齐至 32 位
- 示例：`S20260812143000` + `48291063` → `S2026081214300048291063`
- 冲突重试：`uk_store_code` 唯一键冲突时换号重试，最多 5 次（与 `entity_code` 策略一致）
- 实现位置：`internal/store/service/service.go` 的 `genStoreCode()` 函数

#### 1.3 store_type 枚举校验

service 层定义常量并校验：

```go
const (
    StoreTypeDirect    = "DIRECT"    // 直营
    StoreTypeFranchise = "FRANCHISE" // 加盟
    StoreTypePartner   = "PARTNER"   // 合作
)

var validStoreTypes = map[string]bool{
    StoreTypeDirect: true, StoreTypeFranchise: true, StoreTypePartner: true,
}
```

创建/更新时若 `store_type` 非空且不在枚举内，返回 HTTP 400。

#### 1.4 新增模块

- `internal/store/`（DDD 分层）
  - `domain/store.go` — 领域模型（Store struct）
  - `repository/store_repo.go` — 数据访问（CRUD + 分页 + 归属校验 + 关联数据检查）
  - `service/service.go` — 业务编排（含 store_code 生成 + 枚举校验 + 审计日志写入）
  - `handler/handler.go` — HTTP 接口
- 接口（商户侧鉴权，读 `X-Merchant-Id`）：
  - `POST /v1/merchant/stores` — 创建门店
  - `GET /v1/merchant/stores` — 分页列表（名称/编码/状态筛选）
  - `GET /v1/merchant/stores/:id` — 门店详情
  - `PUT /v1/merchant/stores/:id` — 更新门店
  - `POST /v1/merchant/stores/:id/status` — 启停门店
  - `DELETE /v1/merchant/stores/:id` — 删除门店（**仅无关联码牌/订单**可删，软删除）
- **审计日志**：CREATE/UPDATE/STATUS/DELETE 写入 `t_store_audit_log`

#### 4.2 分账匹配语义（保留 V3 修正）

```
门店订单到达分账引擎
  ↓
1. 查询商户的分账规则集合（按 merchant_id）
  ↓
2. 构造 MatchContext { MerchantID, StoreID, Channel, NowAt }
  ↓
3. 遍历规则集合
  ├─ 规则 store_ids 非空：
  │   ├─ StoreID ∈ store_ids → 命中
  │   └─ StoreID ∉ store_ids → 不命中
  └─ 规则 store_ids 为空：
      └─ 视作"通用规则"，命中
  ↓
4. 在命中集合中按 priority 倒序取首条
  ↓
5. 解析 Rule.Allocations 构建执行计划
  ↓
6. 调用 executor.Execute（从源账户扣减 + 分别入账）
  ↓
7. 分账执行记录写入 store_id（便于排查）
```

#### 4.3 单元测试

- 门店A 命中门店A 专属规则（priority=10，store_ids=[A]）
- 门店B 无专属规则时回退通用规则（priority=5）
- 无任何规则时返回错误（或按业务约定跳过分账）

## 四、关键业务规则

### 4.1 门店与码牌

- 码牌可属于或不绑定门店（**软约束**，兼容历史）
- 门店停用时弹窗确认码牌处置：
  - 选"否"：码牌**仍可收单**，订单仍带门店 ID
  - 选"是"：批量停用码牌（`status=0`）
- 门店重新启用：**不自动恢复**码牌
- 删除门店：**仅当无关联码牌与订单**可删（软删除）

### 4.2 分账匹配语义

```
门店订单到达分账引擎
  ↓
构造 MatchContext { MerchantID, StoreID, Channel, NowAt }
  ↓
遍历规则集合
  ├─ 规则 store_ids 非空：
  │   ├─ StoreID ∈ store_ids → 命中
  │   └─ StoreID ∉ store_ids → 不命中
  └─ 规则 store_ids 为空：
      └─ 视作"通用规则"，命中
  ↓
在命中集合中按 priority 倒序取首条
```

### 4.3 store_code 生成规则

- 格式：`S` + 14 位时间戳 + 8 位随机数字
- 冲突重试：最多 5 次（与 entity_code 策略一致）

### 4.4 store_type 枚举

| 值 | 含义 |
|------|------|
| DIRECT | 直营 |
| FRANCHISE | 加盟 |
| PARTNER | 合作 |

应用层校验，非空时必须在枚举内，否则返回 HTTP 400。

### 4.5 审计日志

`t_store_audit_log` 记录：
- 门店创建/更新/停用/删除
- 门店关联码牌变更

## 六、风险与应对

| 风险 | 应对 |
|------|------|
| 历史码牌未绑门店 | 后端允许 NULL，前端告警引导 |
| 分账 Execute 骨架需重写 | S4 拆为 S4a + S4b，逐步替换硬编码 5:5 |
| OrderModel 缺 store_id | S3 明确列出 4 处代码变更 |
| 迁移序号依赖 | t_store 优先（0015），再加引用列（0016-0018） |
| 停用门店影响在途订单 | 订单状态不受门店状态影响 |
| 门店数量爆炸（>5000） | 分页 + 关键词搜索 + 按商户隔离 + KPI 缓存 |
| 删除门店数据孤儿 | 软删除 + 仅无关联数据可删 |
| 审计缺失 | 关键操作写入 `t_store_audit_log` |
